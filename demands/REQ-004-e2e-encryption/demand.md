## 基本信息

- 需求编号: REQ-004
- 项目代号: e2e-encryption
- 优先级: P1
- 状态: 草稿
- 创建日期: 2026-09-17
- 关联: REQ-001（备份客户端 MVP）+ REQ-002（测试基建）

## 需求描述

在 REQ-001 MVP 之上加一层**用户级 AES-256-GCM 端到端加密**——文件上传前在客户端加密，文件名也加密；远端 WebDAV 服务端（包括 OpenList 实例和任何中间人）**完全看不到明文**。

这是 Sprint 1 retrospective 第 5 节"应该做"的二期功能 #2——隐私卖点。

## 用户故事

- **作为一个** 关注隐私的用户
  **我想要** 上传的照片视频在服务端也是密文
  **以便于** 即使 OpenList 实例被攻破，我的备份数据也不会泄露

- **作为一个** 多设备用户
  **我想要** 在新设备首次配对时输入主密码，本地派生加密密钥
  **以便于** 密钥永不离开本机，远端无从获取

## 功能要求

### F1. 密钥派生

- F1.1 用户首次启动时设置"主密码"（master password）
- F1.2 主密码 + salt → PBKDF2（迭代 ≥ 100,000）→ 32 字节 master key
- F1.3 master key 存 KeyStore（**不**存盘），仅运行时持有
- F1.4 支持"忘记主密码 = 数据无法恢复"显式提示（无密码重置通道）

### F2. 文件加密（AES-256-GCM）

- F2.1 每个文件用 random 12-byte nonce
- F2.2 文件分块加密（chunk 4MB），每块一个 nonce
- F2.3 每块附加 16-byte GCM tag（认证加密，防中间人）
- F2.4 文件格式（远端存储）：
  ```
  [4 bytes: magic "WDVE"]
  [4 bytes: version=1]
  [12 bytes: header nonce]
  [32 bytes: header tag over plaintext of [orig_name|orig_size|chunk_count]]
  [N bytes: chunk_data] (chunk_data = 4MB chunk + 12B nonce + 16B tag)
  ```

### F3. 文件名加密

- F3.1 远端文件名 = base64url(AES-256-GCM(master_key, "wdv-name", orig_name))，加 `.wde` 后缀
- F3.2 远端路径 / 父目录名同理加密
- F3.3 客户端维护"本地路径 ↔ 远端路径"映射（数据库存储，加密）

### F4. 加密/解密流程

- F4.1 备份时：
  - 读本地明文 → 切 chunk
  - 每 chunk AES-GCM 加密 → 拼成 .wde 格式
  - 整文件 PUT 到远端
- F4.2 下载预览时：
  - GET 远端 .wde 文件
  - 解 header → 取原文件名 / size / chunk_count
  - 按 chunk 解密 → 拼成明文
  - 写本地缓存 / 喂预览组件
- F4.3 加密过程**完全在后台线程**，不阻塞 UI

### F5. 密钥导出 / 导入（二期 / 不做）

- 不做（MVP 不支持）
- 用户体验：换设备 = 重新设主密码 + 重新上传所有文件

### F6. 与 REQ-001 的集成

- F6.1 AC-09 "不删远端"继续生效——加密路径下 DELETE 也不允许
- F6.2 AC-07 断点续传重写策略：加密文件上传失败的"重传" = 整文件重传（OpenList 不支持追加，参见 REQ-001 §4.2 修订版）
- F6.3 AC-08 指数退避继续生效
- F6.4 增量同步（AC-06 首末 1MB sha1）改为：先解 header 再算 hash（性能开销约 1.2x）

### F7. 配置开关

- F7.1 端点配置增加"启用端到端加密"开关
- F7.2 关闭时 = 不加密，文件明文上传（兼容 REQ-001 行为）
- F7.3 开启时 = 强制加密，明文上传失败

### F8. 错误处理

- F8.1 主密码错误 → UI 提示"密码错误，解密失败"
- F8.2 文件被破坏（tag 不匹配） → 提示"文件损坏"，跳过不重传
- F8.3 KeyStore 不可用 → 同 AC-02 fallback，UI 标注"加密不可用"，**关闭此端点的加密选项**

## 非功能要求

- **加密性能**：100MB 视频 ≤ 5 秒（手机端，AES-NI 硬件加速）
- **内存峰值**：chunk 大小 4MB，单 chunk 加密 ≤ 16MB 内存占用
- **存储开销**：每文件 + 64 bytes（header + tag）≈ 0.00006% 开销
- **不可逆**：主密码丢失 = 数据永久丢失

## 验收标准（待 Dev 完成后细化）

粗略 AC：
- AC-01: 用户能设置主密码 + 派生密钥
- AC-02: 文件加密后远端不可读（手动 curl 验证头部是密文）
- AC-03: 文件名加密后远端不可识别（手动 curl 看远端文件名是 base64）
- AC-04: 解密 roundtrip 字节完整（对比本地 hash 与解密后 hash）
- AC-05: 主密码错误 → 提示且不渲染密码
- AC-06: 与 REQ-001 增量同步兼容
- AC-07: 加密开关关闭 = 明文上传（兼容 REQ-001 行为）
- AC-08: 真值测试：AES-256-GCM tag 验证拦截篡改
- AC-09: 不删远端（AC-09 继续生效）
- AC-10: 性能：100MB 加密 ≤ 5 秒

## 安全模型

- **信任边界**：客户端（App）信任；远端 WebDAV / OpenList / 中间人**不**信任
- **威胁模型**：
  - 攻击者拿到服务端数据库 → 只能看到密文（保护）
  - 攻击者拿到主密码 + 服务端 → 可解密（无法避免；安全设计目标不是防本地入侵）
  - 主密码弱 → PBKDF2 迭代次数保底
- **不防**：
  - 客户端被 root（攻击者从设备本身拿明文）
  - 用户主动泄露主密码
  - 设备丢失 + 主密码弱
